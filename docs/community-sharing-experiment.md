# 사용자 발견 행사 공유 실험

브랜치: `experiment/community-event-sharing`
기반: `feat/settings-simplification`의 설정 개편 커밋 `93ec3df`.

## 사용 흐름

1. 사진·문서에서 인식한 행사를 확인하고 기존처럼 캘린더에 저장한다.
2. ‘내 일정 → 행사 공유 관리 (실험)’에서 저장한 행사를 선택한다. 목록·동선 보기 모두 같은 진입점을 제공한다.
3. 공개 내용을 확인하고 ‘공개하고 공유’를 누른다. 기본은 비공개다.
4. 다른 사용자는 ‘추천 → 학교·활동 지역으로 추천받기’에서 환경을 선택한다. ‘설정 → 추천 → 내 추천 환경’에서도 수정할 수 있다.
5. 추천 카드의 출처 배지와 ‘전체 / 웹에서 찾은 행사 / 사용자 공유’ 필터로 출처를 구분한다.
6. 공유 관리에서 다시 선택해 공유를 취소한다. 개인 일정 취소도 공유를 철회한다.

학교·활동 지역·연령대는 모두 선택사항이다. 이름이나 사용자 ID를 추천 화면에 표시하지 않는다. 환경 정보는 공유 행사 메타데이터에도 저장하므로 비밀 정보로 취급해서는 안 된다.

## 데이터와 추천

- 개인 `events` 행과 별개의 공용 카탈로그 행을 만든다. 원본 사진·문서, 캘린더 ID·일정 ID, 알림, 주소 상세는 복사하지 않는다.
- 공유 대상은 사용자가 명시적으로 확인한 행사명·장소명·시간·설명·분류·태그·참가비·마감일·출처 링크다. 저장 후 수정한 설명도 공개될 수 있음을 확인 화면에서 알린다.
- 공유한 사람과 원본 행사에 대한 연결을 보존하고, 같은 사람의 반복 공유는 하나의 ID를 유지한다. 공유 취소·계정 삭제 시 공용 행을 삭제한다.
- 공용 행 삭제로 다른 사용자의 이미 저장된 캘린더 일정은 지우지 않는다. 공유본 수정은 취소 후 재공유한다. PostgreSQL RPC의 반복 호출은 같은 ID의 공개 정보를 갱신한다.
- 기존 관심사 점수에 학교 일치 +8, 지역 일치 +5, 연령대 일치 +2를 더한다. 관심사 기록이 없어도 환경이 맞는 공유 행사를 추천할 수 있다. 개인화나 추천이 꺼져 있으면 기존대로 추천하지 않는다.
- 내 공유, 지난 행사, 마감된 행사, 이미 저장한 행사와 일정 충돌은 제외한다.
- 학교·지역명은 현재 문자열 정확 일치다. 학교 인증·참가 자격 판정·GPS 거리 계산·집단 저장 수 가중치는 아직 구현하지 않았다. 행사별 참가 조건은 원 안내를 확인해야 한다.
- 다른 사용자가 올린 동일 행사의 통합, 신고·검수, 그룹 제한 공개는 후속 과제다. 이번 실험의 공유는 전체 공개다.

## 출처

- 새 웹 탐색 결과: 서버가 `origin_kind=web`로 기록.
- 사용자 공유: 서버 또는 인증 RPC만 `origin_kind=shared`로 생성.
- 시연 데이터: `시연용 예시 행사`로 표시.
- 관리자 등록 등 나머지: `등록된 행사`로 표시. 링크가 있다는 이유만으로 새 관리자 등록을 웹 탐색으로 분류하지 않는다.
- 기존 DB 행은 `legacy`이며, 기존 출처 URL이 있으면 웹, 시연 태그가 있으면 예시 데이터로 추정한다.
- 추천 응답은 공유자 ID와 환경 메타데이터를 제외한다. Supabase 카탈로그 자체는 기존처럼 인증 사용자가 읽을 수 있으므로 학교·지역 등의 메타데이터를 비공개 정보로 약속하지 않는다.

## 적용

SQLite는 서버 시작 시 컬럼과 인덱스를 추가한다.
Supabase는 기존 두 마이그레이션 이후 `supabase/migrations/20261028000000_community_sharing.sql`을 적용해야 한다.
운영 DB에는 자동 적용하지 않았다. 앱·서버·DB를 함께 업데이트해야 한다.

API:

- `PATCH /v1/profile`: `school`, `region`, `ageBand` (`under20`, `20s`, `30s`, `40plus`, 빈 문자열).
- `POST /v1/events/:id/share`: `{ "confirmPublic": true }`. 내가 저장한 일정만 공개 가능.
- `DELETE /v1/events/:id/share`: 내 공유만 철회.
- `GET /v1/me`: 개인 일정별 `shared` 상태 포함.
- `GET /v1/recommendations`: 카드별 `originKind` 포함.

## 검증

Node.js 22.16으로 공유 API·접근 제어·개인 정보 제외·환경 매칭·철회·출처 테스트를 실행했다.
PGlite의 실제 PostgreSQL 엔진으로 기존 마이그레이션과 신규 마이그레이션을 순서대로 적용하고 RLS·RPC 권한·환경 갱신을 검증했다.
이는 로컬 엔진 검증이며 운영 Supabase에 연결한 검증은 아니다.

```powershell
cd server
node --test test/community.test.js test/personalization.test.js test/cloud-store.test.js
# PostgreSQL 검증은 별도 설치한 @electric-sql/pglite 모듈의 file URL을 지정한다.
$env:CUE_PGLITE_MODULE = 'file:///path/to/node_modules/@electric-sql/pglite/dist/index.js'
node --test test/community-postgres.test.js
```

전체 서버 테스트의 기존 실패 3건은 기준 커밋에서도 동일하게 재현된다:
Windows의 열린 SQLite 파일 정리 실패, POSIX 파일 권한 기대값 차이, KOPIS 분야 기대값 불일치.
Flutter SDK가 없어 앱 분석·위젯 테스트·폰 실행은 아직 검증하지 못했다.
